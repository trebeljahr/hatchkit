## 3D generation

Single image → 3D mesh (GLB). Five options — pick by quality, license, and intended product category.

| Service | Model | License | Notes |
|---|---|---|---|
| `3d-sam-objects` | **SAM 3D Objects** (Meta) | Open weights | Object reconstruction from an image. Default selection. |
| `3d-sam-body` | **SAM 3D Body** (Meta) | Open weights | Posed human-body reconstruction. For apparel / try-on. |
| `3d-hunyuan` | **Hunyuan3D 2.1** (Tencent) | Tencent Community License† | The bundled Modal pipeline loads the 2.1 model. |
| `3d-trellis` | **TRELLIS 2** (Microsoft) | MIT | Image-to-3D pipeline. |
| `3d-extraction` | **TripoSR** (Stability AI) | MIT | Retained for existing integrations. |

†Review the Tencent Hunyuan 3D 2.1 Community License, including its territory restrictions and separate licence requirement above its monthly-active-user threshold.

Choose a pipeline by its accepted input, output, license, and measured results on your own images. The bundled examples do not establish a quality ranking.

## Vision, audio, custom

| Service | Model | Input → Output |
|---|---|---|
| `image-recognition` | CLIP | image → labels + scores |
| `subtitles` | Whisper large-v3 | audio / video → SRT / VTT |
| `background-removal` | rembg `birefnet-general` | image → RGBA with alpha |
| `custom-hf` | _any HuggingFace model_ | configurable per use case |

For `custom-hf`, Hatchkit collects a Hugging Face model ID and GPU type. It does not ship a custom-model template or provision an Inference Endpoint. Supply and verify the deployment yourself.

## Deployment platforms

| Platform | Current behavior |
|---|---|
| **Modal** | Runs `modal deploy pipeline.py` in the selected service's Modal directory. Requires the Modal CLI and authentication. |
| **RunPod** | Prints manual Docker build/push directions and an endpoint placeholder. No endpoint provisioning. |
| **Hugging Face** | Prints setup guidance and a model URL. No Inference Endpoints API call. |
| **Replicate** | Prints a `cog push` direction and the generic predictions URL. No model publishing. |

Configure credentials with `hatchkit config add modal`, `runpod`, `hf`, or `replicate`. Tokens go to the OS keychain. Configuration alone does not complete a deployment.

The bundled service directories contain Modal pipelines. They do not contain the RunPod or Replicate directories named by the manual directions. Prepare those platform-specific packages yourself before using them.

## The deploy flow

After Terraform and Coolify setup, create deploys selected service/platform pairs and records returned endpoint values. Existing service records can be reused through the wizard.

For Modal, Hatchkit parses the deployment URL from CLI output. If parsing fails, it returns an example URL. For other platforms, returned values are placeholders or inferred URLs. A registry entry therefore does not prove an endpoint exists or is healthy.

The create summary prints `ML_*_ENDPOINT` values to add to Coolify. It does not automatically inject them. Verify each endpoint, its authentication, and its request/response contract before configuring the app. Multiple-platform selections use the first platform as the default `ML_BACKEND`.

## Pipeline anatomy

Each bundled template under `services/ml/<service>/modal/pipeline.py` defines model loading, image dependencies, a GPU function, and a public endpoint. Inspect that file for model-specific parameters and requirements.

The five 3D endpoints accept `multipart/form-data` (`file=...`) or JSON (`{ image_base64: "..." }`) and return raw GLB bytes with `model/gltf-binary` content type. Other services have their own output contracts. Verify compatibility before switching a model.

## Reuse across projects

Hatchkit records the default platform under the service name. Additional platforms use `<service>@<platform>` keys. Inspect the registry with `hatchkit config`. The wizard can reuse a recorded endpoint or let you select it for redeployment.

Recheck manually configured endpoints before reuse. Registry metadata can contain values returned by an incomplete platform deployment.
