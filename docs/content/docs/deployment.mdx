An open documentation tab can outlive the release that served it. This site keeps older files so navigation still works after a release.

The production site at [hatchkit.trebeljahr.com](https://hatchkit.trebeljahr.com) is a static export on a Cloudflare Worker.
The Worker has static assets and no script, so Cloudflare serves the files directly.
Asset requests do not count toward the Workers daily request limit.
A Workers route on the `trebeljahr.com` zone sends the hostname to the Worker.

## Release a new version

The [release workflow](https://github.com/trebeljahr/hatchkit/blob/main/.github/workflows/deploy.yml) runs on each push to `main` that changes the docs.

1. It exports the pages with `next build`.
2. It copies the hashed JavaScript files of the two previous releases into the export. The file list comes from `/release-assets.json` on the live site. Each file must match its recorded SHA-256 hash.
3. It writes `_headers`, `_redirects` and `releases.json`, and checks the Workers Free limits.
4. It uploads a new Worker version with `wrangler versions upload`. Visitors still get the current version.
5. The deploy job activates the new version with `wrangler versions deploy`. It then waits until the homepage and `/version.json` report the new commit for 30 seconds.

Upload and activation are separate steps. A one-step deploy can serve new HTML a few seconds before its JavaScript files are available.

To roll back, run the workflow by hand with operation `deploy`, an earlier version ID and that version's commit.
`wrangler versions list` in `docs/` shows each version's commit as its tag.

## Keep open tabs usable

A Worker version serves only the files it was uploaded with.
Each upload therefore carries the JavaScript files of the two releases before it.
A tab from one of those releases can still load the rest of its code.

Next.js sends its deployment ID with each page-data request.
Every response from this site names the current deployment ID.
When a tab from an older release navigates, Next.js sees the different ID and loads the target page in full.
The tab never mixes page data from one build with code from another.

Tabs outside the three-release window reload their current URL.
The URL keeps its query and fragment.
The window counts releases, so two quick releases can expire a tab sooner than two slow releases.
This policy suits documentation pages. Editors and games need durable user state before they can use the same policy.

## Build the static export locally

Run these commands from `docs/`:

```bash
pnpm install
pnpm build
```

The output is `docs/out/`. `npx wrangler dev` in `docs/` serves it with the production trailing-slash and 404 handling.
For a separate GitHub Pages setup, see [the `gh-pages` reference](./gh-pages).
