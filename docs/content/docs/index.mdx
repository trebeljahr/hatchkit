## What it does

Hatchkit is an interactive CLI that scaffolds, provisions, and deploys full-stack TypeScript products on infrastructure you own.

One command takes you from empty folder to:

- a fresh repo based on a TypeScript starter (websockets, Stripe, auth, analytics, S3, desktop/mobile — opt-in),
- stable HTTPS local-dev URLs for phone/tablet testing over Tailscale + Caddy,
- a GitHub repository,
- DNS + a Hetzner VPS + a Coolify app (via Terraform) — or a push to an existing server you already operate,
- project-scoped GlitchTip error tracking, Plausible analytics, and Listmonk + SES email,
- ML service templates with automated Modal deployment and manual setup paths for other platforms.

Secrets are encrypted with dotenvx; private keys live in the OS keychain. Provider tokens and private keys stay outside Git.

## Why it exists

Starting a new product is the same toil every time: pick a starter, wire up auth, pick error tracking, pick analytics, register a domain, point DNS, configure a server, set up a deployment pipeline, copy twenty env vars between dashboards. Hatchkit encodes the opinionated, repeatable parts so you can spend the first day on _product_, not on yak-shaving.

## Design principles

- **No vendor lock-in.** Your code, your GitHub repo, your Coolify, your server, your domain. Hatchkit is an orchestrator, not a platform.
- **Lazy prompting.** You only get asked about a provider when you actually need it. `doctor` + `config` let you fix things without running the wizard again.
- **Secrets stay out of git in plaintext.** dotenvx encrypts `.env.production` (the committed at-rest store), the OS keychain holds provider tokens and per-project private keys, and `sync` pushes resolved values into Coolify, which is what the running container reads.
- **Project-specific output.** Create strips unselected starter code, runs additive feature generators, and applies operational modules.
